# NDFL-calculator-deposit-2026

**Калькулятор НДФЛ с процентов по вкладам в 2026 году** — одностраничный веб-сервис для бухгалтерской компании: считает налог с процентов по всем вкладам за год, объясняет расчёт простым языком, показывает разбивку по банкам и собирает заявку на консультацию бухгалтера.

## Задача

С 2026 года в России действует налог на проценты по вкладам: необлагаемый лимит считается как **1 000 000 ₽ × ключевая ставка ЦБ РФ**, а со сверхлимитной части взимается НДФЛ по прогрессии **13 % / 15 %**. Обывателю самостоятельно посчитать это сложно, а ошибки стоят денег.

Сервис решает три задачи бухгалтерской компании:

1. **Помочь клиенту** — мгновенно посчитать налог по всем вкладам и объяснить, почему получилась именно такая сумма.
2. **Снять нагрузку с бухгалтера** — ответ на типовой вопрос выдаётся без звонка.
3. **Собрать лид** — под расчётом стоит форма записи на консультацию с результатом расчёта в теле заявки.

Подробное техническое задание — [docs/TZ.md](docs/TZ.md).

## Возможности

- **Расчёт по всем вкладам сразу** — повторяемый блок «Вклад»: банк, сумма процентов за год, отметка «не облагается».
- **Автоматический необлагаемый лимит** — `1 000 000 ₽ × K %`, ключевая ставка меняется в одном поле, лимит пересчитывается мгновенно.
- **Прогрессия 13 % / 15 %** — порог 2,4 млн ₽ применяется к налоговой базе (проценты минус лимит), как в ст. 224 НК РФ.
- **Разбивка по вкладам** — налог распределяется пропорционально процентам, сумма строк сходится с итогом до копейки.
- **Объяснение простым языком** — три сценария текста: налог 0, 13 % и 15 %, плюс подсказка про срок уплаты (до 1 декабря следующего года).
- **Умный ввод сумм** — `1 234 567,89 ₽`: разряды разделяются пробелом, дробная часть через запятую, поле ограничено по длине.
- **Валидация до расчёта** — красная подсветка, текст ошибки, кнопка «Рассчитать» не срабатывает на кривых данных; запрет `Infinity` и сумм свыше 10¹² ₽.
- **Печать отчёта** — отдельное окно с результатом и корректной стилизацией под печать.
- **Сбор заявки** — имя, телефон с маской `+7 (___) ___-__-__`, обязательное согласие на обработку ПДн (152-ФЗ), защита от двойной отправки.
- **Демо-режим лидов** — без настроенного эндпоинта заявки сохраняются в `localStorage` браузера и автоматически удаляются через 72 часа; страница заявок предупреждает, что данные видит любой, кто пользуется этим браузером.
- **Адаптивность** — от 320 px до десктопа, таблица результата прокручивается горизонтально, шрифт полей 16 px (без автозума в iOS Safari).

## Как считает калькулятор

Вход: ключевая ставка `K` (%) и список вкладов (суммы только в рублях).

```
Шаг 1. Лимит        = 1 000 000 × K / 100          K = 16 → 160 000 ₽
Шаг 2. Учёт         = суммы вкладов с чекбоксом «≤ 1 % / эскроу» обнуляются
Шаг 3. Облагаемые   = Σ процентов по облагаемым вкладам
Шаг 4. База         = max(0, Облагаемые − Лимит)
Шаг 5. Налог        = если База ≤ 2 400 000:  База × 13 %
                      иначе: 2 400 000 × 13 % + (База − 2 400 000) × 15 %
Шаг 6. Итог         = округление налога до целого рубля (ст. 52 НК РФ)
Шаг 7. Разбивка     = налог_i = Налог × (проценты_i / Облагаемые),
                      разница округления добрасывается в последнюю строку
```

Эталонные примеры из ТЗ (K = 16 %):

| Сценарий | Вход | Результат |
|---|---|---|
| Вклад ниже лимита | 120 000 ₽ | **0 ₽** |
| Два вклада выше лимита | 100 000 + 90 000 ₽ | **3 900 ₽** (база 30 000 ₽ × 13 %) |
| Превышение 2,4 млн | 1 500 000 + 1 500 000 ₽ | **378 000 ₽** (312 000 + 66 000) |
| Вклад со ставкой ≤ 1 % | 5 000 000 ₽, чекбокс включён | **0 ₽** |
| Ровно на лимите | 160 000 ₽ | **0 ₽** |

## Технологии

- **HTML5 / CSS3 / ванильный JavaScript** — без фреймворков и без сборщика: страница открывается двойным кликом, работает из любого статического хостинга.
- **Ноль внешних зависимостей в рантайме** — ни CDN, ни шрифтов, ни скриптов извне: supply-chain риски отсутствуют.
- **Node.js + jsdom** — только для автотестов (`devDependencies`), в продакшен не идут.
- **GitHub Pages** — демоверсия живёт в ветке `gh-pages` (статика из `public/`).


## Сбор заявок (лиды)

- Поле `LEAD_ENDPOINT` в `public/app.js` — **публичный URL без секретов**; токены и подписи живут только на сервере.
- Пустое значение = демо-режим: заявка уходит в `localStorage` c TTL 72 часа, форма честно сообщает об этом пользователю.
- Тело запроса: `{ name, phone, calc_result: { limit, taxable_base, tax }, page, created_at }` — бухгалтер видит результат расчёта сразу в заявке.
- Валидация: имя 2–50 символов, ровно 11 цифр телефона, обязательное согласие на обработку ПДн, `AbortController` с таймаутом 10 с, кнопка блокируется на время запроса.

## Ограничения

- Расчёт носит информационный характер и не заменяет консультацию бухгалтера.
- Только рублёвые вклады: валютных вкладов и поля курса ЦБ в интерфейсе нет.
- Декларации не подаются и к банкам сервис не подключается — налог считает ФНС и присылает уведомление.
- Ключевая ставка вводится вручную (подсказка ведёт на cbr.ru); значения по умолчанию заданы в `CONFIG.DEFAULT_KEY_RATE`.
- Демо-режим лидов не отправляет заявки на сервер: для продакшена достаточно заполнить `LEAD_ENDPOINT`.
